# 0017. 레시피 입력 구조 기록과 열 매핑

- 상태: 채택
- 날짜: 2026-11-16
- 관련: FR-22, #82

## 배경
레시피를 저장한 뒤 다음 주 엑셀의 열 이름이 바뀌면(`매출` → `금액`) 실행이 열을 찾지 못하고 실패했다.
실행 때 무엇이 바뀌었는지 알려면 저장 시점의 입력 구조가 있어야 하고, 사용자가 대응 관계를 알려 주면
AI 없이 그대로 실행되어야 한다. 결과는 원래 열 이름으로 실행한 것과 같아야 한다.

## 결정
- `save_recipe`는 `$input`이 엑셀이면 GridCraft로 읽은 구조를 레시피 JSON의 `input_schema`
  (`sheets`·`columns`·`column_types`)에 저장한다. 파일 경로는 저장하지 않는다.
  열 형식은 `number`·`text`·`boolean`·`mixed`·`empty` 다섯 가지다.
- 실행 전에 입력 구조를 다시 읽어, 레시피가 쓰는 열(`group_by`·`value`)이 빠졌으면 단계를 실행하지 않고
  규칙 기반 매핑 제안(같은 위치 +2, 같은 형식 +1, 이름 유사도 0.5 이상 +1, 점수순·위치순으로 1:1 배정)을 돌려준다.
  `input_schema`가 없는 옛 레시피는 기존 FR-11 점검을 그대로 쓴다.
- `docmill run --map 새 열=원래 열`은 실행 동안 contextvar로 활성화되고, 엑셀을 읽는 `read_table`이 머리글만
  원래 이름으로 바꿔 읽는다. 원본 파일은 건드리지 않는다.
- MCP `run_recipe` 도구 인자는 바꾸지 않는다. 구조가 다르면 결과 JSON에 `missing`·`suggestions`가 담긴다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| 레시피 단계 인자(`value`)를 새 열 이름으로 바꿔 실행 | 구현이 단순하다 | 그래프 계열 이름·문구가 새 이름이 되어 결과가 달라진다 | "원래 열 이름 입력과 같은 결과" 기준을 못 맞춘다 |
| 머리글을 고친 임시 엑셀 사본을 만들어 실행 | 도구 코드 변경이 없다 | 숫자 출처(provenance)가 사라지는 임시 파일을 가리키고, 엔진 저장 과정에서 값이 바뀔 위험이 있다 | 출처 추적(FR-21)과 충돌 |
| 열 이름 유사도만으로 제안 | 단순하다 | `매출`→`금액`처럼 이름이 전혀 다른 변경을 못 잡는다 | 위치·형식 규칙이 필요 |

## 결과
- 열 이름이 바뀐 입력은 결과 파일 없이 0이 아닌 종료 코드와 함께 제안 JSON을 stdout에 출력한다.
- 제안은 입력만으로 정해지며(정렬된 순회, 난수·시각 없음) 네트워크·AI를 쓰지 않는다.
- 레시피에 쓰이지 않는 열이 빠진 경우는 실행을 막지 않는다. 열 형식 변화 감지가 필요해지면 다시 본다.
