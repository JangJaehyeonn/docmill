# 0026. 살아 있는 문서: provenance로 다시 집계하고 숫자 글자만 고친다

- 상태: 채택
- 날짜: 2026-11-18
- 관련: FR-37, FR-21, #124

## 배경
원본 엑셀이 바뀌면 보고서의 그래프 값과 합계·비중 문장을 새 값으로 고쳐야 한다(FR-37).
원본이 그대로면 문서는 바이트 단위로 그대로여야 하고, 바뀐 위치(이전 값 → 새 값)를 알려야 한다.
studio는 원본이 저장되면 연결된 열린 문서에 제안을 띄워야 하며, AI는 부르지 않는다.

## 결정
- `refresh_links`는 문서 옆 `provenance.json`(ADR 0016)의 출처를 연결로 보고, 원본 xlsx 셀을
  zip·XML로 직접 읽어 `excel_to_report_ppt`와 같은 규칙(이름과 값이 모두 있는 행, 이름 strip,
  이름순 합)으로 다시 집계한다. 같은 값 범위·이름 범위를 쓰는 출처는 한 표로 묶는다.
- 문서는 ADR 0024의 바이트 위치(span) 방식으로 고친다. 그래프 점은 `c:v` 글자, 본문은 도형 안
  숫자 글자만 바꾼다. 도형 안 숫자는 provenance 순서대로 앞에서부터 짝짓는다. 바뀐 숫자가 없으면
  아무 파일도 쓰지 않는다. 고친 뒤 provenance.json의 값·자릿수·빠진 행도 갱신한다.
- 숫자만으로 맞출 수 없는 변화(요약의 최대 항목 변경, 새로 생긴 항목)는 고치지 않고 `warnings`로 알린다.
- studio는 열린 탭마다 `/api/links`로 연결된 원본(작업 폴더 안)의 수정 시각을 2초마다 확인하고,
  원본이 provenance.json보다 나중에 저장됐으면 제안을 띄운다. [새 숫자로 고치기]는 열린 편집기를
  먼저 저장한 뒤 `docmill refresh-links`를 부르고 탭을 다시 불러온다. 고치는 동안 편집기 입력은 막는다.
- 새로 고친 뒤 provenance.json의 수정 시각을 **이번에 읽은 원본 중 가장 늦은 수정 시각**(읽기 전에 잼)으로
  맞춘다. 읽은 뒤에 원본이 다시 저장되면 그 시각이 더 늦으므로 studio가 제안을 다시 띄운다. 저장 형식(FR-21)은
  바꾸지 않는다.
- 본문에서 항목명 자리(`이름: 값`의 이름, `최대: 이름 값`의 이름)의 숫자는 짝짓기에서 뺀다. 런이 나뉘어도
  도형의 글자를 이어서 찾는다.
- 저장은 새 문서·새 출처 파일·원래 문서 복원본을 모두 임시 파일로 끝까지 쓴 뒤 이름 바꾸기만 한다. 쓰기에서
  실패하면 아무것도 바뀌지 않고, 출처 파일 교체가 실패하면 복원본을 이름 바꾸기로 되돌린다.
- 같은 문서의 새로 고침은 문서 폴더의 잠금 파일(`.<문서 이름>.docmill-lock`, 환경 변수와 무관)로 막고,
  60초 안에 잠금을 얻지 못하면 `lock` 단계 실패로 돌려준다.
- studio는 `docmill refresh-links --workspace <작업 폴더>`로 부른다. CLI는 문서·출처 파일·원본의 실제 경로
  (링크를 따라간 경로)가 작업 폴더 안인지 확인하고 그 경로로 읽는다. 상대 경로 원본이 작업 폴더 기준과
  문서 폴더 기준에 서로 다른 파일로 모두 있으면 고르지 않고 실패로 알린다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| 보고서를 처음부터 다시 만들기 | 문장 구성까지 새로 맞음 | 만든 뒤 사람이 고친 내용·서식이 사라짐, 원래 인자가 기록에 없음 | 사용자의 편집을 지워 버림 |
| GridCraft 엔진으로 원본 읽기 | 보고서와 같은 읽기 경로 | 엔진 프로세스가 필요하고 느림, 셀 주소 대신 표 단위로만 읽음 | provenance는 셀 주소 기준이라 직접 읽는 편이 정확하고 가벼움 |
| studio가 탭을 연 순간의 원본 판을 기준으로 비교 | provenance와 무관 | 탭을 연 직후 저장되면 놓침(경쟁 상태) | 탭을 연 시점에 의존하지 않음. 단 원본 수정 시각이 provenance.json보다 더 늦을 때만 감지하며, 두 시각이 같으면 감지하지 못함 |
| 파일 감시(fs.watch) | 즉시 반응 | 플랫폼마다 동작이 다르고 교체 저장을 놓치기 쉬움 | 2초 간격 stat이 단순하고 충분함 |

## 결과
- 사람이 고친 문서 내용과 서식은 그대로 두고 숫자만 최신으로 맞춘다. 같은 입력이면 같은 결과다.
- 원본에 행이 추가돼 기록된 셀 범위를 벗어나면 그 행은 집계에 들어가지 않는다. 새 항목은 경고로만 알린다.
- 원본 판을 수정 시각으로 판단하므로, 내용이 같아도 다시 저장하면 제안이 뜰 수 있다(고쳐도 바뀐 곳 0).
  바뀐 곳이 없어도 provenance.json 수정 시각은 읽은 원본 판으로 맞추므로 제안은 한 번 고치면 사라진다.
- provenance를 만드는 문서가 pptx 밖으로 늘어나면(FR-44) 해당 형식의 숫자 고치기를 같은 방식으로 추가한다.
