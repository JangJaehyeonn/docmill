# 0018. 도구 선택 평가 세트와 보고서 형식

- 상태: 채택
- 날짜: 2026-11-16
- 관련: FR-23, #83

## 배경
업무 도구 6개의 설명을 바꾸면 AI가 요청에 맞는 도구와 인자를 고르는 정확도가 달라진다.
바꾸기 전후를 숫자로 비교하려면 고정된 요청 세트와 같은 방식의 채점, 날짜별 보고서가 필요하다.
모델 호출은 사용자의 Claude Code 구독 인증으로만 하고 API 키는 쓰지 않아야 하며,
CI에서는 모델 없이 채점 로직만 검증해야 한다.

## 결정
- 시나리오는 `evals/scenarios/NN-<id>.json` 한 파일에 하나: `id`, `request`,
  `expected: {tool: 도구 이름 또는 null, args: {핵심 인자}}`. 파일 이름 순으로 실행한다.
- 채점: 도구 일치는 고른 도구 == 기대 도구(도구 없음은 null끼리). 인자 일치는 도구가 맞고
  기대 인자의 모든 키가 같은 값으로 들어 있을 때다(추가 인자는 허용, 문자열은 경로의 파일 이름만
  같아도 일치). 모델 호출이 실패·시간 초과면 불일치로 센다.
- 보고서: `evals/reports/<날짜>.json`(시나리오별 일치 여부, 기대 도구별 개수·일치율, `none`은
  도구 없음)과 같은 내용의 `.md`. 날짜는 인자로만 받고, 키 순서·줄바꿈을 고정해 같은 응답이면
  바이트 단위로 같다.
- 실제 모델(`--model claude-code`)은 `claude -p`에 `--mcp-config`로 docmill 서버만 연결하고
  `stream-json` 출력에서 처음 고른 `mcp__docmill__*` 호출을 읽는다. docmill 도구는 허용 목록에
  넣지 않아 실제 실행은 거부된다. 자식 프로세스 환경에서 `ANTHROPIC_*` 변수는 모두 뺀다.
- 테스트·CI는 `--model fake --responses <json>`으로 정해진 응답을 채점한다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| Anthropic API로 직접 호출 | 응답 형식이 단순하다 | API 키가 필요하다 | 요구사항이 구독 인증만 허용 |
| 인자 완전 일치 채점 | 규칙이 단순하다 | 모델이 기본값 인자를 더 넣으면 오답이 된다 | 핵심 인자만 보는 것이 목적에 맞음 |
| 시나리오를 한 파일에 모음 | 파일 수가 적다 | 추가·리뷰 시 충돌이 잦다 | 파일당 하나가 diff 보기 쉬움 |

## 결과
도구 설명을 바꾼 뒤 `docmill eval --date ...`과 `docmill eval --compare 이전.json 새.json`으로
도구별 변화를 바로 볼 수 있다. Claude Code CLI의 stream-json 형식이 바뀌면 `parse_stream`을 고친다.
실제 모델 평가는 사람이 로컬에서 돌리며 CI에서는 돌리지 않는다.
