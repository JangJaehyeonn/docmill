# 0031. 반복 작업 기록과 레시피 제안

- 상태: 채택
- 날짜: 2026-11-24
- 관련: FR-49, #157

## 배경
FR-49는 studio에서 일어난 도구 호출을 남기고, 입력 파일만 다른 같은 순서의 작업이 3번 이상
반복되면 레시피로 저장하자고 제안해야 한다. 기존 실행 로그(`tool_runs`, FR-16)는 인자를 요약·절단해
남기므로 레시피를 다시 만들 수 없고, 세션 기록(`SessionRecorder`, FR-09)은 서버 프로세스가 끝나면 사라진다.

## 결정
같은 `docmill.db`에 `session_calls` 표를 추가해, MCP 세션(서버 프로세스)마다 세션 ID를 붙여
레시피로 만들 수 있는 업무 도구(`RECIPE_TOOLS`)의 **성공한 호출 인자 전체와 산출물 경로**를 남긴다.
반복 판단은 호출을 `build_steps`로 정규화(입력 경로 → `$변수`, 앞 단계 산출물 → `$stepN`)한 단계 목록이
같으면 같은 작업으로 보고, 세션 안에서 겹치지 않게 나온 횟수를 모든 세션에 걸쳐 센다.
더 짧은 작업의 되풀이이거나 같은 횟수 이상 반복된 더 긴 작업의 일부인 것은 제안하지 않는다.
수락하면 `save_recipe`와 같은 저장 함수(`write_recipe`)로 저장하고, 수락한 패턴은 `learned_patterns`에 남겨
다시 제안하지 않는다. 진입점은 CLI `docmill recipes suggest [--accept 이름] [--pick N]`이다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| `tool_runs`에 인자 JSON 열 추가 | 표 하나 | 모든 도구(개인정보 도구 포함)의 인자가 길게 남는다 | 요약만 남기는 FR-16 원칙과 충돌 |
| 레시피 파일 폴더에 세션 기록 JSON 저장 | DB 불필요 | 동시 기록·순서 보장이 어렵다 | SQLite가 이미 있다 |
| 새 MCP 도구로 제안 노출 | AI가 바로 제안 | 요구사항에 없는 도구 노출 | CLAUDE.md 설계 원칙 |

## 결과
반복 감지는 저장된 순서만 보고 시각·난수를 쓰지 않아 같은 기록이면 같은 제안이 나온다.
최근 500건만 훑으므로 오래된 반복은 잊힌다. 성공한 편집(`guarded_edit`)도 `session_calls`에 남기지만
run_recipe로 다시 실행할 수 없어 레시피 단계와 반복 후보에는 넣지 않고, 반복 감지에서는 순서를 끊는
경계로만 쓴다. 러너가 편집 도구를 지원하면 `RECIPE_TOOLS`에 넣어 제안 대상으로 넓힌다.
