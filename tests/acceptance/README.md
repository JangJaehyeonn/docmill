# 인수 기준 테스트 (보호 폴더)

이 폴더의 테스트는 요구사항 정의서의 **인수 기준**을 코드로 옮긴 것이다.
구현 PR이 통과해야 하는 기준이므로 다음 규칙을 지킨다.

- 이 폴더는 **사람(CODEOWNERS) 승인으로만** 바뀐다.
- Claude Code는 이 폴더를 수정하거나 테스트를 건너뛰게(`skip`, `xfail`) 만들 수 없다.
- 모든 테스트에 `@pytest.mark.fr("FR-xx")`를 붙인다. 없으면 테스트 수집이 실패한다.
  `DOCMILL_ACTIVE_FRS`에 든 요구사항의 테스트만 실행된다 (끝난 요구사항 + 지금 PR의 요구사항).

보호 장치는 세 겹이다. 실제로 막는 것은 1·2번이고, 3번은 빠른 경고다.
1. CODEOWNERS + main 브랜치 규칙: 이 폴더를 바꾸는 PR은 재현의 승인 없이 머지되지 않는다.
2. `.claude/settings.json`: Claude Code가 이 폴더를 편집·생성하지 못하게 막는다.
3. CI `protected-paths` 검사: `claude/*` 브랜치에서 이 폴더를 바꾸면 실패한다 (다른 브랜치는 1번이 막는다).
- 새 Phase가 시작되면 `acceptance-tests` 워크플로가 이 Phase의 테스트 초안을 만들고, 재현이 PR 하나로 한 번에 승인한다.
- 고정 샘플 파일은 `tests/fixtures/`에 둔다.

구현이 이 테스트를 통과하지 못하면 테스트가 아니라 구현을 고친다.
요구사항 자체가 잘못됐다면 이슈에 `needs-human` 라벨을 붙이고 멈춘다.
