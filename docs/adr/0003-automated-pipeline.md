# 0003. 개발은 Claude Code, 검증은 CI, 리뷰는 CodeRabbit, 사람은 관문 세 곳만

- 상태: 채택
- 날짜: 2026-11-11

## 배경
이전 팀 프로젝트에서 겪은 문제
- 기획 채팅에서 받은 프롬프트를 Claude Code에 복사하는 수작업
- code owner 사람 승인이 병목이 되어 자동화를 멈춤
- CI 없이 자동 머지해 검증 장치가 없음
- 왜 그 기술을 썼는지 설명하지 못함

## 결정
- 요구사항(`docs/requirements/issues.toml`) → GitHub 이슈 → Claude Code 구현 → PR.
- **검증은 CI**(ruff·mypy·pytest·인수 테스트), **리뷰는 CodeRabbit**. 둘 다 통과하면 자동 머지.
- CodeRabbit 변경 요청, CI 실패, 머지 충돌은 Claude Code가 자동으로 고친다. 같은 PR에서 3회 실패하면 `needs-human`.
- 인수 테스트·자동화 설정·요구사항은 보호 경로로 두어 AI가 바꾸지 못하게 한다 (CODEOWNERS + CI 가드 + Claude 권한 거부).
- 사람의 관문은 세 곳: Phase 0 엔진 검증, Phase별 인수 테스트 PR 승인(한 번에), 릴리스 승인.
- 새 의존성·구조 결정은 같은 PR에 ADR을 남기고 CodeRabbit이 확인한다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| 모든 PR을 사람이 승인 | 안전 | 병목 (이전 프로젝트에서 실패) | 자동화 목표와 반대 |
| CI 없이 에이전트 리뷰만으로 머지 | 빠름 | 실제 동작 검증 없음 | 품질 보장 불가 |
| 완전 무인 (릴리스까지) | 손이 안 감 | 잘못된 배포를 막을 장치 없음 | 공개 패키지라 위험 |

## 결과
- 사람은 Phase당 한 번의 테스트 승인과 릴리스 버튼만 누른다.
- 인수 테스트의 품질이 전체 품질을 좌우하므로, 테스트 PR 승인은 꼼꼼히 해야 한다.
