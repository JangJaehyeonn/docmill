# 0004. CI와 Claude 작업 환경에 실제 문서 엔진 설치

- 상태: 채택
- 날짜: 2026-11-12
- 관련: FR-02, FR-03, #16

## 배경
Phase 1 인수 테스트 중 엔진이 필요한 테스트(`@pytest.mark.engine`)는 엔진 실행 파일이 없으면 건너뛴다.
CI와 Claude 작업 환경에 엔진이 없으면 FR-02·FR-03의 핵심 기준(실제 엔진 호출, 같은 입력이면 같은 파일)이
한 번도 검증되지 않은 채 통과한다.

## 결정
`.github/actions/setup-engines`가 GridCraft 0.9.0, DeckCraft 0.9.0, WordCraft 0.8.0의 Linux 릴리스를 내려받아 PATH에 넣는다.
CI와 Claude가 구현·수정하는 모든 워크플로가 이 액션을 쓴다. 설치 후 버전 명령이 실패하면 작업이 실패한다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| 엔진 없이 가짜 엔진만으로 테스트 | 빠르고 외부 의존 없음 | 실제 엔진 동작·재현성을 검증 못 함 | 인수 기준이 실제 엔진을 요구 |
| 소스에서 빌드 | 어떤 버전이든 가능 | 작업마다 수십 분 | 너무 느림 |
| 릴리스 바이너리 내려받기 | 빠름, Phase 0과 같은 버전 | 외부 다운로드 의존 | 채택 (버전 고정 + SHA256SUMS 확인) |

## 결과
- 엔진 테스트가 CI에서 실제로 돈다. 엔진 버전을 올리면 재현성·호환성을 다시 확인해야 한다(Phase 0 절차).
- 체크섬은 같은 릴리스의 SHA256SUMS.txt로 확인하므로 전송 중 손상은 잡지만, 릴리스 자체가 바뀌는 경우는 막지 못한다.
  필요하면 해시를 이 저장소에 고정한다.
