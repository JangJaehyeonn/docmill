# 0024. guarded_edit: OOXML 요소 단위 지문과 원본 뼈대 끼워 넣기

- 상태: 채택
- 날짜: 2026-11-17
- 관련: FR-31, #98

## 배경
`guarded_edit`는 편집 범위(슬라이드·도형 id, 시트·셀 범위, 문단 번호) 밖이 바뀌면 원래대로 되돌려야 한다.
인수 기준은 범위 밖 슬라이드·도형 XML이 원본과 **바이트 단위로** 같고, 같은 입력이면 결과 파일도 바이트 단위로 같을 것을 요구한다.
XML을 파싱해 다시 쓰면(ElementTree 등) 접두사·따옴표·속성 순서가 바뀌고, 엔진(DeckCraft 등)으로 저장하면 파일 전체가 다시 직렬화되어
범위 밖 바이트를 지킬 수 없다.

## 결정
- 문서를 zip 파트로 읽고, 지킬 파트(슬라이드·시트·`word/document.xml`)는 태그를 훑어 단위(spTree 바로 아래 도형, row 아래 셀, body 바로 아래 문단)의 바이트 위치만 찾는다 (`tools/ooxml.py`).
- 편집 전에 모든 파트와 단위, 단위 밖 구조의 지문(C14N 정규화 XML의 SHA-256)을 남긴다.
- 편집 후 결과는 **원본 파트를 뼈대로** 범위 안에서 지문이 달라진 단위만 편집본 조각으로 바꿔 끼워 만든다. 범위 밖에서 지문이 달라진 단위·구조·파트는 원본 바이트를 그대로 두고 `reverted`에 위치를 적는다. 지문이 같으면(정규화상 같은 변경) 원본 바이트를 쓴다.
- zip은 원본 항목 순서·날짜·압축 방식대로 다시 쓴다 → 같은 입력이면 같은 바이트.
- 기본 편집(`set_text`·`set_cells`·`set_paragraphs`)은 엔진 대신 같은 방식으로 요소 조각만 고친다 (`tools/edits.py`). 편집 함수는 `Editor` 형식으로 바꿔 끼울 수 있어, 테스트용 편집 함수나 나중의 엔진 편집도 같은 지키기 단계를 거친다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| 엔진(DeckCraft·GridCraft·WordCraft)으로 편집 후 비교 | 엔진 규칙 재사용 | 저장 시 전체 재직렬화, 엔진 버전에 따라 바이트가 달라짐 | 범위 밖 바이트 보존·재현성 인수 기준을 지킬 수 없음 |
| ElementTree로 파싱·수정·직렬화 | 구현이 쉽다 | 접두사(`ns0:`)·속성 순서가 바뀜 | 범위 밖 XML이 원본과 달라짐 |
| lxml 의존성 추가 | 접두사 보존 | 새 의존성, 직렬화 차이는 여전히 있음 | 표준 라이브러리로 충분 |

## 결과
- 범위 밖은 항상 원본 바이트로 남는다. 되돌린 위치(`슬라이드 3 도형 2`, `시트 1 셀 C10`, `문단 5`, `파일 …`)를 돌려준다.
- 기본 편집은 이미 있는 도형·셀·문단만 고친다 (새 셀·도형 추가는 하지 않는다). 범위 안 새 단위는 끼울 자리가 없어 `추가됨`으로 되돌린다.
- 단위 밖 구조(예: spTree 머리, sheetData 밖, sectPr)의 변경은 범위 밖으로 보고 되돌린다. 범위를 슬라이드·시트 전체로 주면 그 파트는 통째로 편집본을 쓴다.
