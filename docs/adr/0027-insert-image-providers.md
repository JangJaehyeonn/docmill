# 0027. 이미지 삽입: 교체 가능한 제공자, 지키기 뒤에 그림 파트 덧붙이기

- 상태: 채택
- 날짜: 2026-11-19
- 관련: FR-42, FR-31, #129

## 배경
`insert_image`는 설명 문장으로 이미지를 만들어 pptx 슬라이드·docx·hwp 문단에 넣는다(FR-42).
제공자(OpenAI·Gemini 등)는 바꿀 수 있어야 하고 키는 환경 변수로만 받는다. 테스트는 실제 제공자를 부르지 않는다.
pptx·docx 편집은 `guarded_edit`의 지키기(ADR 0024)를 거쳐 범위 밖이 바뀌지 않아야 한다.

## 결정
- 제공자는 `generate_image(provider, prompt)` 한 함수 뒤에 둔다. 새 제공자는 키 환경 변수 이름과 PNG를
  돌려주는 함수를 표(`PROVIDER_KEYS`)에 추가하면 된다. 표준 라이브러리(`urllib`)만 써서 의존성을 늘리지 않는다.
  키가 없으면 예외 대신 `{"disabled": true, "message": "이미지 생성이 꺼져 있어요 …", "env": 이름}`을 돌려준다.
- 가짜 제공자 `fake`는 `DOCMILL_FAKE_IMAGE_PNG`가 가리키는 PNG를 그대로 돌려준다.
- pptx·docx는 `guard_edit`에 그림 요소(`p:pic`·`w:drawing`)만 넣는 편집 함수를 넘긴다. 슬라이드는 한 장 전체,
  docx는 문단 하나가 범위다. 그림 파일·관계·`[Content_Types].xml`은 범위 밖 파트라 지키기가 되돌리므로
  지키기를 거친 뒤에 덧붙인다. 관계 id·파일 이름은 기존 것에서 순서대로 정해 같은 입력이면 같은 바이트다.
- docx는 문단 수를 바꾸지 않도록 지정한 문단 끝에 그림 글자 상자(run)를 붙인다. hwp는 rhwp(`@rhwp/core`)로
  문단 뒤에 새 문단을 만들어 그림을 넣고 hwp로 저장한다(`hwp_image.mjs`).

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| 제공자 SDK 사용 | 응답 처리 편함 | 새 의존성, 제공자마다 추가 | 요청이 단순해 urllib로 충분 |
| docx에 새 문단 추가 | 그림이 문단 뒤에 독립으로 놓임 | 지키기가 문단 추가를 범위 밖 변경으로 되돌림 | 지키기와 충돌 |

## 결과
- 제공자 추가가 표 한 줄과 함수 하나다. 실제 제공자 호출은 자동 테스트하지 않는다(키·비용·재현성).
- hwp는 입력이 hwpx여도 hwp로 저장한다. 그림 크기는 가로 최대 약 10.6cm(hwp)·15cm(docx)로 제한한다.
