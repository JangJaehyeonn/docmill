# 0001. 자체 웹 서비스 대신 Python MCP 서버로 만든다

- 상태: 채택
- 날짜: 2026-11-11
- 관련: FR-01, FR-02

## 배경
"말로 시키면 오피스 파일을 만들어 주는" 경험은 ChatGPT·Claude·MS 365 Copilot이 이미 제공한다.
1인 개발로 채팅 화면·AI·업로드 UI까지 만들면 범위가 크고, AI 비용도 운영자가 부담해야 한다.

## 결정
- 채팅과 AI는 사용자가 이미 쓰는 앱(Claude·ChatGPT)을 쓰고, docmill은 **MCP 서버**로 업무 도구만 제공한다.
- 언어는 Python, 서버는 공식 MCP Python SDK 2.x(`MCPServer`)를 쓴다.
- 연결은 stdio(로컬)부터 만들고, HTTP(원격)는 Phase 4에서 추가한다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
| --- | --- | --- | --- |
| React + FastAPI 웹 서비스 | 화면을 마음대로 설계 | 채팅·업로드·AI 비용을 모두 직접 부담 | 범용 챗봇과 정면 경쟁, 범위 과다 |
| Spring Boot + Spring AI | 기존 경험 활용 | MCP 예제·생태계가 Python보다 적음 | MCP·에이전트 도구가 Python 중심 |
| 엔진 MCP를 그대로 연결 | 개발할 것이 없음 | 저수준 도구라 AI가 매번 수십 개를 조합 | 기여·차별점이 없음 |

## 결과
- AI 비용은 사용자의 기존 구독이 부담하고, 운영자는 서버를 운영하지 않아도 된다.
- 웹 버전 AI 앱 연결은 원격 모드가 필요하고, 앱별 정책에 따라 제한될 수 있다.
